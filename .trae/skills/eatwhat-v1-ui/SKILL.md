# 吃啥 · 第一版 UI 基准

本 SKILL 沉淀「吃啥」（解决今天吃什么的网站/小程序/App）第一版已确认的界面与交互设计。后面所有开发、逻辑设计与迭代都以本文件为基准，不要偏离既定交互形态，除非用户明确要求改版。

## 1. 产品定位与端起
- 解决「今天不知道吃啥」。
- 内容来源分两类：**菜谱**（自己做）与**餐厅**（点外卖 / 堂食），二者可在同一餐同时存在（既点外卖又做几道菜）。
- 后端 Python + 轻量 SQLite；前端多端（Web / App / 小程序），uni-app。

## 2. 导航骨架（五个底部 Tab，恒定显示）
任何页面都保留底部五个标签，点击 label 高亮当前页：
1. **推荐**（原「今日」）：问候 + 转盘「帮我选一个」+ 快捷口味筛选（两行横滑 grid） + 「为您推荐」列表（餐厅 1 家 + 菜谱 3 道，可「换一个」随机轮换）。
2. **菜谱**（页面顶部标题叫「吃这些」）：顶部候选区 + 「全部菜谱」（Tab 切换「参考菜谱 / 我的菜谱」）。
3. **冰箱**：库存（在库/待采购）+ 新增编辑。
4. **餐厅**：我的餐厅收藏列表 + 新增/编辑（含 emoji 图标、星级评分）。
5. **我的**：个人资料区 + 干饭成员（各自口味偏好维护）+ 功能菜单。

## 3. 核心概念与交互

### 3.1 吃这些（候选收件箱）
- 「+候选」把菜谱或餐厅加入「吃这些」；已加入的按钮变「✓ 已选」并禁用；从吃这些移除后自动恢复「+候选」。
- 加入候选**不跳转页面**，停留原页并原地刷新。
- 菜谱候选：其所需食材与冰箱在库比对，**缺的食材自动代入待采购（带数量）**；移除候选时**按量回退**。
- 餐厅候选：只进候选，**不参与采购计算**。
- 候选可点击进入详情；菜谱详情在本场景下仅查看（不编辑），主操作是「开始做这道菜」。

### 3.2 计时（可多道并行）
- 在吃这些列表行内直接「▶计时 / ⏸停止 / ⏹取消」，无需进详情；也可进详情操作。
- 多道菜计时互不影响；开始计时后进详情不再显示「开始做」，改为实时走表控件。
- 待采购累计：多道候选用到同种缺货食材时数量叠加（×N）。

### 3.3 转盘「帮我选一个」
- 可选项 = **菜谱 + 餐厅混合池**，抽中显示类型徽章（菜谱/餐厅）。
- 结果页：+候选 与 再抽一次 并排；抽中即加入候选；再抽一次按钮复位。

### 3.4 推荐页快捷筛选
- 「跟谁一起吃？」：干饭成员 chip **单行横滑**（横向 scroll-view，一行排开）。
- 「快捷筛一下」：口味标签 chip **两行横滑 grid**（grid `grid-template-rows: repeat(2, max-content)` + `grid-auto-flow: column`，按列填充，两行内横向滑动）。
- 选中某个「干饭成员」时自动把他的口味标签默认勾上，可手动取消；多选取并集。

### 3.5 干饭成员（用餐人维护，入口在「我的」）
- 每个用餐人分别维护：姓名 + 口味偏好（从全局口味标签池中点选 chip）。
- 新增成员默认空口味，后续点「口味」按钮进入编辑弹窗勾选。

### 3.6 厨房技巧（内容社区 + 审核）
- 所有人可见、都能新增；只能改/删自己创建的。
- 可勾选是否公开；新增/编辑一律「待管理员审核」（`audit_enabled=0` 时跳过直接通过）。
- 状态显示：⏳ 待审核 / ✅ 已公开 / 🚫 未通过。
- 管理员审核入口在 PC 管理端 → 厨房技巧审核。

### 3.7 菜谱体系
- **我的菜谱**：可新建、可编辑（详情里编辑回填表单）、可删除、可加入吃这些。自己创建的名称不能重名。
- **参考菜谱**：管理员录入（`source='admin'`），只读；可「＋ 候选」加入吃这些，或「＋ 存进我的菜谱」复制成自己的再编辑。
- **菜谱 Tab 结构**：顶部药丸 Tab 切换「参考菜谱(数量) / 我的菜谱(数量)」，空态文案分 Tab 显示。「＋ 新建」按钮仅在「我的菜谱」Tab 出现。
- **菜品 emoji**：4列 × 两行半 emoji 候选网格（高度 `max-height: ~200rpx`，末行半露暗示下滑），只支持点选，不手动输入。图标来源 `recipe_emoji_pool` 配置（管理端维护）。
- **封面渐变**：横滑一行 12 个渐变色块候选（`cover_grad_pool` 配置），用户直接点选或可手动输入渐变字符串。
- **所需食材**：唯一来源是**食材库**（见 3.11），与冰箱库存/待采购两套解耦。选择交互：大类胶囊横滑 → 当前大类食材清单点选 ✓ → 底部「输入并收录进食材库」。
- 菜谱列表/详情封面：背景用 `recipes.cover` 字段直接存渐变字符串，emoji 用 `recipes.em` 字段。

### 3.8 冰箱维护
- 在库/待采购均可新增、编辑（复用新增表单回填）、删除（✕）。
- 食材选择：大类胶囊**两行横滑 grid**（grid 两行 + 横向 scroll-view），大类 chip 显示 `icon + 名称`；当前大类下食材清单也显示 `食材icon + 名称`。
- 食材名称**只从食材库点选**（不支持自由输入）；没找到可「＋ 收录」进食材库。
- 日期控件统一用 `<picker mode="date">`，不在表单里直接手输日期。
- 在库额外字段：存放位置（冷藏/冷冻/常温）、购买日期、保质期分段（1-3天/一周/一个月/长期）。

### 3.9 餐厅收藏
- 新增与编辑共用同一表单；字段包括：名称、类型、人均、到达耗时(分)、交通工具、星级（★★★★★ 点选评分，金色 #f5a623）、招牌菜、emoji 图标（候选网格 4列两行半）。
- 列表卡片：横排显示 `emoji icon + 店名`，右侧 `⭐ N`。
- 详情页大封面：背景按 id 轮换 4 色渐变（k1~k4），中央 emoji 来自 `shops.icon` 字段。
- 图标候选来源 `shop_icon_pool` 配置（管理端维护）。

### 3.10 饮食记录
- 类型：自己做 / 餐厅 / 外卖；日历按天聚合、点日期看当日记录。
- 记录支持编辑（改名/改类型/改日期）与删除。
- 月份切换：点中间年月标签弹年月选择器（`picker mode=date fields=month`）直达任意年月；取消横向滑动切月。
- 选中日标题不显示「· N 顿」统计。

### 3.11 体重记录
- 字段：日期（picker mode=date）、体重(kg)、体脂(%，可空)。
- 列表 + 内联表单（H5/App/小程序通用，避免 showModal editable 限制）。
- 最新概览卡片：当前体重 + 环比 emoji（📈📉➖）+ 变化值；体脂率存在时也显示。
- 曲线图：SVG 折线 + 数据点，体重(紫) + 体脂(橙) 双系列；首尾日期标于底部。

### 3.12 食材库（可维护实体）
- **公共 + 私有双层模型**：公共层由管理端维护（scope=public, user_id=1），私有层由用户自己补录（scope=user, user_id=当前用户）。
- **合并视图**：用户端看到的 = 自己私有层 + 公共层未覆盖部分（按名称去重，自己的优先）。
- **同名校验**：公共层已有同名食材/大类时，用户不能补录私有条目，提示"公共库已有，可直接选"。
- 食材字段：名称 + 大类 + emoji 图标（可选，空则列表渲染 fallback 大类 icon）。
- 大类字段：名称 + emoji 图标（必填）+ sort（编排顺序即展示顺序）。
- 分类编排：在食材库页「大类 Tab」↑↓ 排序；改名级联更新归入该大类的所有食材；删除归入「其他」兜底。
- 食材图标候选来源 `ingredient_icon_pool` 配置（管理端维护）；大类图标候选来源 `cat_icon_pool` 配置。
- 权限：scope=public 的条目需管理员权限才能改/删；scope=user 只能改/删自己的。

### 3.13 口味标签
- **全局维护实体**（独立的 `taste_tags` 表 + CRUD API），菜谱筛选、干饭成员偏好、首页推荐筛一下**都读同一份**。
- 入口：**我的 → 🏷️ 口味标签**。
- 候选网格：6列 × 两行 + 滚动（`grid-template-columns: repeat(6, 1fr); max-height: ~200rpx; overflow-y: auto`）。
- **删除保护**：被菜谱或干饭成员使用时不允许删除，删除前校验引用关系。

### 3.14 配置表系统（configs）
所有运行时配置集中在 `configs(key, value)` 表，管理端「系统配置」区统一维护：

| 配置 key | 用途 | 前端消费位置 |
|---|---|---|
| `audit_enabled` | 厨房技巧审核开关，关则新增/修改直接通过 | 后端 tips.py |
| `expiry_threshold_days` | 临期阈值（天），实时计算在库状态 | 后端 fridge.py |
| `admin_passcode` | 管理端口令，默认 123456 | 后端 admin.py |
| `ingredient_icon_pool` | 食材 emoji 候选池（逗号分隔） | mine-ingredients / fridge-edit |
| `cat_icon_pool` | 大类 emoji 候选池（逗号分隔） | mine-ingredients / fridge-edit |
| `recipe_emoji_pool` | 菜谱 emoji 候选池（逗号分隔） | recipe-edit |
| `shop_icon_pool` | 餐厅 emoji 候选池（逗号分隔） | shop.vue |
| `cover_grad_pool` | 菜谱封面渐变池（逗号分隔） | recipe-edit |

管理端 UI：每项一个 textarea 输入 + 实时预览区 + 失焦自动保存。

### 3.15 PC 管理端（桌面宽屏）
- 入口：**我的 → 🖥️ 管理端（PC）**，仅桌面宽屏（`windowWidth >= 1024`）可见。
- 布局：左侧菜单（`position: sticky; top: 0`）+ 右侧内容区（布局用 **px** 非 rpx，避免桌面 rpx 放大）。
- 定位：**只管公共资源**（用户/参考菜谱/食材库/技巧审核/系统配置）；**个人数据一律不上管理端**。
- 8 个菜单区：
  1. **统计**：公共资源计数卡（用户数/参考菜谱/食材库/大类/技巧总数/技巧待审），`adminApi.stats()` 实时聚合。
  2. **用户管理**：CRUD（新增/改名/切换角色/删除）；内置管理员 id=1 不可删/降级（UI 置灰 + 后端拦截）。
  3. **厨房技巧审核**：列表 + 状态分段筛选（全部/待审核/已公开/未通过）+ 关键词搜索 + 「加载更多」分页；待审条目显示 ✓通过 / ✕退回。
  4. **参考菜谱**：可录入/编辑/删除（source=admin）。
  5. **食材库**：只管 scope=public 的食材。
  6. **食材大类**：只管 scope=public 的大类。
  7. **系统配置**：全部配置 textarea + 实时预览 + 失焦自动保存。
  8. （封面图库已移除，封面渐变由 `cover_grad_pool` 配置替代）
- 登录鉴权：本地会话标记 `eat_admin`；口令存配置表 `admin_passcode`（默认 123456），`POST /admin/login` 校验；仅门控管理台，不影响移动端 API。

### 3.17 后端字段命名规范 & 前端映射约定
- 后端 DB 列统一用 **snake_case**（`body_fat`, `cover_grad_pool`, `audit_enabled` 等）。
- 前端内部用**友好语义名**（`fat`, `category`, `public` 等），在 `load()` 里做「后端 → 前端」映射，在 `save()` 里做反向映射。
- **已确认需要双向映射的 3 个字段对**：
  - `body_fat` ↔ `fat`（体重记录）
  - `cat` ↔ `category`（厨房技巧分类）
  - `pub` ↔ `public`（厨房技巧公开开关）
- 其他模块前后端字段名一致，无需映射。

## 4. 样式与实现约定

### 4.1 emoji 候选网格统一设计
所有 emoji 候选网格（菜谱菜品、餐厅图标、食材图标）统一：
- **4 列 × 两行半**（`grid-template-columns: repeat(4, 1fr); max-height: ~200rpx; overflow-y: auto`）
- cell 固定高度约 76rpx（不用 aspect-ratio，避免跟宽度不确定）
- 末行半露高度暗示"下面还有，可下滑"

### 4.2 两行横滑 grid 统一设计
所有两行横滑（食材库归类大类、冰箱编辑大类、首页推荐筛一下）统一：
- 外层 `<scroll-view scroll-x>`（配合 `white-space: nowrap`）+ 内层 **`display: inline-grid`**
- `grid-template-rows: repeat(2, max-content)` 锁死两行
- `grid-auto-flow: column` + `grid-auto-columns: max-content` 按列填充
- `vertical-align: top` 消除行内盒的基线留白
- 单行横滑同理，内层用 **`display: inline-flex`**
- ⚠️ 内层不可用块级 `flex`/`grid`：块级盒会被撑到容器宽度，小程序 `scroll-view scroll-x` 检查不到更宽的内容宽度 → 滚不动（H5 靠溢出区机制照常能滚，极易漏测）。详见 4.6

### 4.3 日期控件统一
所有表单日期输入统一用 `<picker mode="date">`，不在 `<input>` 里手动手输日期字符串。
占位文案「选择日期」，选中后显示 `YYYY-MM-DD`，选中态高亮品牌色边框。

### 4.4 CSS 变量
- `--brand` 紫 `#4b3fe3` / `--surface` / `--card` / `--bg` / `--border`
- `--text` / `--text-2` / `--danger` / `--warning` / `--success`
- `--radius-lg` 大卡片圆角（默认 16rpx）
- ⚠️ **必须定义在 `App.vue` 的全局 style 里**，不可放 `uni.scss`（原因见 4.6）

### 4.5 其他
- 简洁扁平风格，状态 emoji / pill 辅助。
- 底部 tab 恒定、内屏固定高度、内容区内滚，不随内容高低抖屏。
- 按钮/标签统一文案口径：候选相关一律「+候选 / ✓ 已选」；返回统一 `uni.navigateBack()` 栈式返回。
- 管理端布局用 **px**（非 rpx），避免桌面端 rpx 放大。
- `Vite proxy`：前端用相对路径 `/api`，vite 转发到后端；`vite.config.js` 设 `host: true` 同时监听 IPv4/IPv6。

### 4.6 跨端（微信小程序 / App / H5）兼容基线
一套代码多端编译，以下为已验证的跨端硬约束（违反会在小程序端静默失效，H5 不一定暴露）：

| 项 | 约束 | 原因 |
|---|---|---|
| 编译依赖 | 必须安装 `@dcloudio/uni-mp-weixin`，版本与其它 `@dcloudio/*` 完全一致 | 缺失则 `build:mp-weixin` 直接报错退出 |
| 接口 BASE | H5 用相对路径 `'/api'`（走 vite 代理）；小程序/App 必须绝对 HTTPS 地址 | 小程序 `uni.request` 不支持相对路径，且无代理层 |
| 承载位置 | 统一在 `request.js` 顶部 `const MP_BASE = '...'` 常量承接，用 `// #ifdef H5` / `// #ifndef H5` 条件编译区分 | 部署时只改一行 |
| 全局 CSS 变量 | 定义在 **App.vue 全局 style**；`uni.scss` 只放 SCSS 变量（`$brand` 等），不放任何 CSS 规则 | `uni.scss` 会被注入到每个组件的 `<style lang="scss">`，带 scoped 的页面会编译成 `page[data-v-xxx]`，小程序下 `page` 元素没有 `data-v` 属性 → 变量整段失效、颜色全丢 |
| 横滑容器 | 内层用行内级盒 `inline-flex` / `inline-grid` | 块级盒会被撑到容器宽度，小程序测不到更宽内容 → 滚不动 |
| 图表 | **不可用内联 `<svg>`**；改用绝对定位 view 绘制（线段 = 起点 + 长度 + 旋转角） | 小程序 WXML 不支持内联 SVG 标签 |
| 图表容器 | 必须**固定 rpx 尺寸**（如 `640rpx × 300rpx`） | 保证宽高比恒定，`rotate` 角度才与渲染一致；rpx→px 等比缩放，固定 rpx 在任意屏幕都等比成立 |
| 不支持的单位 | `100dvh` 等用 `/* #ifdef H5 */ ... /* #endif */` 包裹 | 小程序不支持该单位，H5 需要 |
| 窗口尺寸 | 用 `uni.getWindowInfo()` / `uni.getSystemInfoSync()` | 小程序无 `window` 对象，`window.innerWidth` 会报错 |
| DOM/BOM | `window` / `document` / `localStorage` 一律换 `uni.*` 对应 API | 小程序无 DOM/BOM；`uni.getStorageSync` / `uni.request` / `uni.showModal` / `uni.createSelectorQuery` 才跨端安全 |
| 页面级条件编译 | `pages.json` 支持 `// #ifndef MP-WEIXIN` 包裹页面条目；该页面的跳转入口同步用 `<!-- #ifdef H5 -->` 包裹 | 页面被剔除后跳转入口若仍存在，会 `navigateTo` 到不存在的页面 |
| PC 管理端归属 | 管理端页**仅 H5 部署**，小程序包内不含（条件编译剔除） | 管理端是 px 布局 + `windowWidth>=1024` 判定，手机上永不触发；其为最大单页，剔除可显著减小主包 |

真机仍需留意的两点（未做兼容降级）：
1. `display: grid` 使用面很广（emoji 候选、日历、KPI 卡等）——现代基础库支持，安卓低版本 WebView 个别机型有偏差。
2. flex `gap` 用得多——iOS 14 以下不支持 flex gap，会退化为无间距。

### 4.7 UGC 内容安全（小程序提审硬要求）
小程序内有用户生成内容时，微信提审**强制要求**接入内容安全检测，否则大概率被驳回。

- 实现位置：`backend/app/wxsec.py`（msgSecCheck v2）。用标准库 `urllib`，**不新增 HTTP 依赖**。
- 配置项（`configs` 表，管理端/接口可改）：`wx_sec_enabled` 默认 `'0'`、`mp_appid`、`mp_secret`。
- 接入点：厨房技巧的新增/编辑（标题+正文合并送检）、干饭成员的新增/编辑（成员名）。
- **默认关闭**，本地 / H5 开发与既有流程完全不受影响；配好凭证后置 `'1'` 即生效。
- **fail-open 四条**：开关关闭 / 未配凭证 / 微信接口超时或报错 / 无 openid —— 一律放行，避免"检测故障导致用户存不了内容"。
- `suggest` 判定：`risky` 直接拦截；`review` 放行并交由本项目既有的「人工审核」流程兜底（技巧本身就要过审），避免误伤。
- ⚠️ **真正强制生效还需 openid**：msgSecCheck v2 要求 openid，而 openid 需先接 `wx.login` 换 code 的登录流程（项目当前未接）。所以未接登录前本检测不会拦截，接上登录后自动生效，调用方无需再改。

## 5. 落地开发前置校验
在实现任何页面或逻辑前，先对照本基准确认：
- 是否用到底部五 tab / 对应页面归属；
- 是否涉及候选 → 采购代入/回退、计时、用餐人口味联动、审核等既有交互；
- emoji 候选网格是否统一用 4列 × 两行半 + 点选；
- 两行横滑是否统一用 `inline-grid` + `scroll-view scroll-x`；
- 日期控件是否用 picker mode=date，不用手输；
- 复用既有 CSS 变量与组件；
- 是否触碰 4.6 的跨端硬约束（尤其：CSS 变量位置、横滑内层 display、是否用了 `<svg>`）。
