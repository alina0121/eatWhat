# 吃啥 · 第一版 UI 基准

本 SKILL 沉淀「吃啥」（解决今天吃什么的网站/小程序/App）第一版已确认的界面与交互设计。后面所有开发、逻辑设计与迭代都以本文件为基准，不要偏离既定交互形态，除非用户明确要求改版。

## 1. 产品定位与端起
- 解决「今天不知道吃啥」。
- 内容来源分两类：**菜谱**（自己做）与**餐厅**（点外卖 / 堂食），二者可在同一餐同时存在（既点外卖又做几道菜）。
- 后端 Python + 轻量数据库；前端多端（Web / App / 小程序）。

## 2. 导航骨架（五个底部 Tab，恒定显示）
任何页面都保留底部五个标签，点击 label 高亮当前页：
1. **推荐**（原「今日」）：问候 + 转盘「帮我选一个」+ 快捷口味筛选 + 「为您推荐」列表（餐厅 1 家 + 菜谱 3 道，可「换一个」随机轮换）。
2. **菜谱**（页面顶部标题叫「吃这些」）：顶部候选区 + 「按口味筛」标签（横滑单行）+ 「全部菜谱」。
3. **冰箱**：库存（在库/待采购）、食材库、大类维护。
4. **餐厅**：我的餐厅收藏列表 + 新增收藏。
5. **我的**：个人资料 / 饮食统计 / 干饭记录 / 体重记录 / 参考菜谱 / 干饭成员 / 厨房技巧 / 设置。

## 3. 核心概念与交互
### 3.1 吃这些（候选收件箱）
- 「+候选」把菜谱或餐厅加入「吃这些」；已加入的按钮变「✓ 已选」并禁用；从吃这些移除后自动恢复「+候选」。
- 加入候选**不跳转页面**，停留原页并原地刷新。
- 菜谱候选：其所需食材与冰箱在库比对，**缺的食材自动代入待采购（带数量）**；移除候选时**按量回退**。
- 餐厅候选：只进候选，**不参与采购计算**。
- 候选可点击进入详情；菜谱详情在本场景下仅查看（不编辑），主操作是「开始做这道菜」。

### 3.2 计时（可多道并行）
- 在吃这些列表行内直接「▶计时 / ⏸停止 / ⏹取消」，无需进详情；也可进详情操作。
- 多道菜计时互不影响；开始计时后进详情不再显示「开始做」，改为实时走表控件。
- 待采购累计：多道候选用到同种缺货食材时数量叠加（×N）。

### 3.3 转盘「帮我选一个」
- 可选项 = **菜谱 + 餐厅混合池**，抽中显示类型徽章（菜谱/餐厅）。
- 结果页：+候选 与 再抽一次 并排；抽中即加入候选；再抽一次按钮复位。

### 3.4 口味筛选 / 用餐人
- 快捷筛选 chips 单行横滑，为「为您推荐」服务。
- 选中某个「干饭成员」(用餐人) 时自动把他的口味标签默认勾上，可手动取消；多选取并集。

### 3.5 干饭成员（用餐人维护，入口在「我的」）
- 每个用餐人分别维护：姓名、口味偏好（口味/忌口/辣度等）。
- 原「口味偏好」独立入口已并入成员维度，各成员分别维护。

### 3.6 厨房技巧（内容社区 + 审核）
- 所有人可见、都能新增；只能改自己的。
- 可勾选是否公开；新增/编辑一律「待管理员审核」，通过才公开，退回则未通过。
- 卡片点开查看详情（默认两行摘要，点开展开全文与操作）。

### 3.7 菜谱体系
- **我的菜谱**：可新建、可编辑（详情里编辑回填表单）、可删除、可加入吃这些。自己创建的名称不能重名。
- **参考菜谱**：管理员录入，只读；可「＋ 候选」加入吃这些，或「＋ 存进我的菜谱」复制成自己的再编辑。
- **参考菜谱入口**：在「我的」功能菜单的第一项「📚 参考菜谱 · 管理员精选 · 可加入吃这些或我的菜谱」。点击后打开**独立的参考菜谱列表页**（仅列出 `source='admin'` 的菜谱），点击卡片进入**菜谱详情页**；**不要**直接跳转到菜谱 tab（吃这些）功能页。
- 新建菜谱入口在「全部菜谱」标题旁的「＋ 新建菜谱」。
- **所需的食材**来源是**食材库**（见 3.11），与冰箱的库存/待采购两套解耦、独立维护。

### 3.8 冰箱维护
- 在库/待采购均可新增、编辑（复用新增表单回填）、删除（✕）。
- 待采购行额外有「🛒 已采购」——转入在库（购买日期记今天，食材库有大类则自动归类），并删除待采购行；以及「✎ 改」编辑数量。
- 行内双行布局：第一行 图标+名称+操作，第二行 属性+状态 pill（临期橙底白字/充足/待买）。
- 食材大类用**单行横向滑动胶囊**点选（同菜谱页），食材名称可**从食材库点选**或自由输入，空大类提示可**输入并收录进食材库**（交互与菜谱页完全一致）。

### 3.11 食材库（可维护实体）
- 入口：**我的 → 🧺 食材库**；也可在编菜谱/冰箱页通过「＋ 收录」把新食材写入食材库。
- 食材库是菜谱「所需食材」的**唯一来源**，与冰箱在库/待采购两套**解耦、独立维护**（用户并非所有菜谱食材都需采购）。
- 食材字段：名称（唯一，不能重名）+ 大类（分类）。
- **食材大类**是动态可维护实体（`categories` 表：name 唯一 + icon + sort），不再是写死的常量：
  - 在食材库页「大类 Tab」增删/改名/换图标/↑↓排序；改名级联更新所有归入该大类的食材与冰箱在库项；删除后归入「其他」（自动确保该兜底大类存在）。
  - 分类编排顺序即各菜单/筛选的展示顺序。
- 食材库页分「食材 / 大类」两个 Tab，均支持增删改。

### 3.12 各功能入口与交互明细（2026-09 确认）
- **我的**功能菜单顺序：参考菜谱 / 厨房技巧 / 饮食记录 / 体重记录 / 食材库 / 封面图库 / 设置。（「饮食统计」功能已移除，无入口。）
- 底 tab「菜谱」图标用 **📖**（彩色书本；🍽 刀叉多为单色会显示灰色）。
- 食材选择统一交互：**大类单行横滑胶囊（‹ › 步进箭头 + 底部自绘滑轨 thumb，到边箭头置灰）置顶 → 选中 tag 胶囊 → 当前大类食材清单（点选 ✓）→ 底部「输入并收录进食材库」**；菜谱页与冰箱页一致。
- 干饭记录：月份切换用「‹ / ›」点按，点中间年月标签弹**年月选择器**（`picker mode=date fields=month`）直达任意年月；取消横向滑动切月；选中日标题不显示「· N 顿」统计。
- 菜谱详情「所需食材」前的 ✓ 为**只读**在库标识（命中冰箱在库自动打勾），不支持点按切换。

### 3.9 餐厅收藏
- 新增与编辑共用同一表单；含「到达耗时 / 交通工具」字段。

### 3.10 饮食记录
- 类型：自己做 / 餐厅 / 外卖；日历按天聚合、点日期看当日记录。
- 记录支持编辑（改名/改类型）与删除；每条有唯一 id。

### 3.13 菜谱封面（固定封面图库）
- 菜谱封面 = **emoji 图标 + 渐变背景**。封面不再是「按 id 轮换」，改为**管理员维护的固定封面图库实体**。
- 入口：**我的 → 🖼️ 封面图库**（管理员维护：增删改、上下排序；删该封面用它的菜谱自动回退默认封面）。
- 菜谱编辑（ recipe-edit.vue）新增「封面」卡片：**横滑点选**图库封面（emoji 显示在渐变底色上）+ 一项「默认」；保存写 `recipes.cover = 封面id`，且 `em = 该封面 emoji`。
- 渲染：列表/详情用后端返回的 `coverGrad` 作背景、`em` 作图标；未选封面则回退默认渐变（按 id 轮换）。
- 数据模型：`covers(id, emoji, name, grad, sort)`；`recipes` 增 `cover` 列（TEXT，旧库 ALTER 迁移，幂等）。默认种子 12 组（emoji+渐变+名）仅在空表时写入。

### 3.14 PC 管理端（桌面宽屏）
- 新增 `pages/admin/admin.vue`：**左侧菜单 + 右侧内容区**的桌面管理台，复用同一套 API，不改后端业务路由。
- **定位：只管理公共资源**（封面图标、用户、参考菜谱、食材库、技巧审核、系统配置）；**个人数据（我的菜谱/冰箱/干饭/体重/餐厅收藏等）一律不上管理端**，看个人数据去用户端。
- 菜单 7 项：**统计 / 用户管理 / 厨房技巧审核 / 参考菜谱 / 封面图库 / 食材库 & 大类 / 系统配置**（**无「餐厅」**，餐厅属个人收藏）。
- 布局用 **px**（非 rpx，避免桌面 rpx 放大）；FORM 用自绘 mask 弹窗；登录态存 `eat_admin` 本地会话标记（登录成功置 1）。
- **统计**：仅公共资源计数卡（用户数/参考菜谱/食材库/大类/封面图库/技巧总数/技巧待审），数据来自后端 `adminApi.stats()` 实时聚合，无任何个人数据卡片或图表。
- **用户管理**：`adminApi` 提供 /admin/users CRUD（新增/改名/切换角色/删除）；内置管理员 id=1 不可删除/降级（UI 置灰+后端拦截）。
- **参考菜谱**：可**录入 / 编辑 / 删除**（后端已放开 source=admin 的 PUT/DELETE；卡片上有 ✎编辑 / ✕删除，编辑复用同一 modal 回填）。
- **搜索 / 筛选 / 分页**：技巧(关键词 + 状态分段 全部/待审核/已公开/未通过)、参考菜谱、食材均支持关键词过滤；长列表按页加载（默认 20 条，点「加载更多」累加）。
- **登录鉴权**：管理端需口令登录，口令存配置表 `admin_passcode`（默认 `123456`），后端 `POST /admin/login` 校验；仅门控管理台，不影响移动端与其余全 API。口令可在「系统配置」区修改。
- 入口：**我的 → 🖥️ 管理端（PC）**，仅桌面宽屏（`windowWidth >= 1024`）可见；移动端不显示，不影响原 tab 页。

### 3.15 我的数据（用户端个人数据总览）
- 用户端新增 `pages/mine-data/mine-data.vue`，入口在**「我的 → 我的数据」功能菜单第一条**；与管理端公共资源统计**互为对照**：个人数据（我的菜谱/参考菜谱/在库/待采购/吃这些候选/收藏餐厅/干饭/体重）只在用户端看，不上管理端。
- 数据来自后端 `mineApi.stats()`（`GET /mine/stats`）实时聚合，前端只消费结果、不落冗余。
- 页面结构：自绘顶栏（标题「我的数据」+ ‹ 返回）+ 计数概览（8 张计数卡）+ 本月干饭分布（横条比例）+ 体重趋势（柱子归一化）。

## 4. 样式与实现约定
- 简洁扁平：CSS 变量（--brand 紫 #4b3fe3 / --surface / --card / --border / --text / --danger / --warning 等）。
- 底部 tab 恒定、内屏固定高度、内容区内滚，不随内容高低抖屏。
- 按钮/标签统一文案口径：候选相关一律「+候选 / ✓ 已选」；返回统一 back() 栈式返回（二级页可逐级返回）。
- 交互为纯前端单文件原型即可；状态联动、项具备唯一 id，刷新允许重置（不要求持久化）。

## 5. 落地开发前置校验
在实现任何页面或逻辑前，先对照本基准确认：
- 是否用到底部五 tab / 对应页面归属；
- 是否涉及候选 → 采购代入/回退、计时、用餐人口味联动、审核等既有交互；
- 复用既有 CSS 变量与组件（chip/card/ing/type-badge/pbtn/cand/pill 等）。
